# LLMChat32 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 用 Open Watcom 2.0 构建一个 Windows 98 兼容的 Win32+GDI LLM 聊天客户端（三套协议、SSE 流式、TOML 配置、本地会话、中英双语、wolfSSL 静态链接）。

**Architecture:** 单 exe，分层：core（utf/json/toml/session/history/net/http/tls/llm）+ ui（自绘 GDI）。网络在工作线程跑阻塞 socket + wolfSSL 默认 IO，经 PostMessage 回 UI。所有字符串边界经 ui_text_w / ui_text_a 包装。

**Tech Stack:** C89 + Open Watcom 2.0（`-bt=nt -bm -wx`）、wolfSSL v5.9.x-stable（静态）、Winsock 2（ws2_32）、stb_image（背景图与图片消息）。

**Spec:** `docs/superpowers/specs/2026-10-19-llmchat32-design.md`（执行者必须同时读 spec）

## Global Constraints

- 编译：`wcl386/wcc386 -bt=nt -bm -wx`，目标零警告；测试程序用 `-bc`（console）。
- 源文件一律 UTF-8 **无 BOM**（`build.bat` 启动时扫描，发现 BOM 即失败退出）。
- 禁止 `\uXXXX` 转义；禁止非 ASCII 的 `L""` 字面量；`wchar_t` 按 16 位使用（已含 `<stddef.h>` 验证）。
- **任何位置不得把 UTF-8 字节直接传给 ANSI API**。唯一允许的两个出口：`ui_text_w()`（→TextOutW/DrawTextW）与 `ui_text_a()`（→WideCharToMultiByte(CP_ACP) → SetWindowTextA/MessageBoxA 等）。core 层只认 UTF-8。
- 包含 Windows 头：先定义 `WIN32_LEAN_AND_MEAN` 再 `windows.h`，winsock 用 `winsock2.h`（OW 的 windows.h 默认含 winsock.h，冲突，spec §2 已证实）。
- 链接库清单：ws2_32, comdlg32, shell32, gdi32, user32 + wolfssl 静态库。不链接 comctl32/advapi32。
- Winsock 初始化 `WSAStartup(MAKEWORD(2,2))`（Win98 支持 ws2_32）。
- 超时：连接 10s、读写 30s（常量放 net.h，可后配）。
- 文件写一律「先写 `.tmp` 再 rename」；失败（含磁盘满）返回错误码并保留内存数据。
- git 提交信息前缀：任务粒度提交，`feat:`/`test:`/`build:` 等常规约定。
- 测试运行环境：开发机（Win11）直接运行 Win32 console 测试程序；真机 Win98 验证不在本计划自动化范围。

## Review Focus

1. **UTF-8 四字节字符（emoji/生僻字）**：消息收发、折行、长度统计必须正确处理 UTF-16 代理对——`test_utf` 含 U+1F600 往返断言，`test_llm` 流式片段含代理对拆分用例。
2. **SSE 事件跨 chunk 拆分**：`data: {...}` 被 TCP 拆成两半到达——`test_http` 用逐字节 feed 的 mock 验证行解析器。
3. **磁盘满**：history/config 写失败——`test_history` 注入写失败路径断言「返回错误且内存数据不变」，UI 任务验证 MessageBox 路径。
4. **会话 JSON 损坏**：手工编辑过导致解析失败——`test_history` 断言跳过该文件并给出错误信息，启动不崩。
5. **服务端非 2xx + error JSON body（三家格式不同）**：`test_llm` 用 canned 响应断言错误提取为可读字符串，不产生崩溃或空白气泡。
